## 1. 部署建议

### 1.1 家庭云

节点信息：

- 节点名：`homeserver`
- Tailscale IP：`100.65.192.69`
- Tailscale HTTPS 域名：`homeserver.tailed5977.ts.net`
- 角色：主服务节点
- 网络：家庭 Wi-Fi 内网、IPv6、Tailscale
- 服务端口：`3333`
- 部署子路径：`/surveillance`

运行：

- Node.js 服务：`server/dist/index.js`。
- 前端静态文件：`web/dist`，生产模式由 Node.js 服务托管。
- PM2：生产进程管理。
- Tailscale。
- Tailscale MagicDNS 和 HTTPS Certificates。

建议：

- 使用 PM2 保活，项目已提供 `ecosystem.config.cjs`。
- 固定家庭云内网 IP。
- 配置健康检查接口，例如 `/healthz`。
- 日志区分信令日志和访问日志。
- 默认不直接暴露公网端口，公网入口由 `aliserver` 反向代理。
- 旧手机必须通过 HTTPS 域名访问采集页，例如 `https://homeserver.tailed5977.ts.net/surveillance/camera/home`，否则浏览器不会稳定授予摄像头权限。
- Node.js 建议使用 20 LTS 或更新的 LTS 版本。

### 1.2 阿里云

节点信息：

- 节点名：`aliserver`
- Tailscale IP：`100.115.222.54`
- 角色：公网网关与 TURN 兜底节点
- 网络：独立公网 IPv4、Tailscale

运行：

- Nginx。
- coturn。
- Tailscale。

建议：

- Nginx 配置 Let's Encrypt 证书。
- 安全组只开放必要端口。
- Nginx 通过 Tailscale 反向代理到 `homeserver` 的 `100.65.192.69`。
- coturn relay 端口范围收窄，便于安全组管理。
- 监控 TURN 带宽，避免异常消耗。
- coturn 必须配置公网 `external-ip`，避免返回云厂商 VPC 内网地址。
- 使用 Trickle ICE 验证 `srflx` 和 `relay` candidate，确认 STUN/TURN 都真正可用。

### 1.3 旧安卓手机

节点信息：

- 节点名：`mi10ultra`
- Tailscale IP：`100.126.250.4`
- 角色：采集端
- 网络：家庭 Wi-Fi、IPv6、Tailscale

建议：

- 使用稳定电源供电。
- 关闭过度省电策略。
- 保持屏幕或浏览器前台运行，实际机型需要测试。
- 降低分辨率和帧率，减少发热。
- 优先使用后置摄像头。
- 优先访问家庭云的 HTTPS 域名，而不是裸 IP HTTP。
- 长时间运行时关注 Tailscale、电池、发热和浏览器后台保活策略。

## 4. 环境变量

**单一配置来源：根目录 `ecosystem.config.cjs`。**

- `**env`**：生产 PM2 默认使用的块；`homeserver` 上不要依赖 `.env`（`NODE_ENV=production` 时服务端也不会为「补全配置」去读 `.env`，仅当你显式放了根目录 `.env` 时 dotenv 才会加载并可能覆盖同名键——仍不建议生产使用 `.env` 作为主力来源）。
- `**env_development**`：本地开发使用。`npm run dev` 会先由 `scripts/run-dev.mjs` 把该块合并进环境变量，再启动 server 与 Vite，使 `PORT`、`ALLOWED_ORIGINS`、`VITE_*` 等与生态文件一致；服务端在 `NODE_ENV !== production` 时也会从同文件读取 `env_development` 中尚未设置的键（便于只起 `server` 子包时仍对齐配置）。本地若需临时覆盖，可选用根目录 `.env`（见仓库根目录 `env.development.example`），dotenv 默认不覆盖已在环境中的键。
- **开发态 PM2**：`npx pm2 start ecosystem.config.cjs --env development` 使用 `env_development` 启动已构建的 `server/dist`（需先 `npm run build`）。

以下为生产用 `**env` 中与文档对齐的典型取值**（实际以仓库内文件为准）：

```env
PORT=3333
NODE_ENV=production
PUBLIC_BASE_PATH=/surveillance
ROOM_TOKEN=change-me
MAX_VIEWERS_PER_ROOM=2
ALLOWED_ORIGINS=https://homeserver.tailed5977.ts.net,https://www.kaitool.top,http://localhost:5173,http://localhost:3333
ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":"stun:global.stun.twilio.com:3478"}]
```

前端 `**VITE_*` 为构建期变量**，不进 PM2 runtime；家庭云请使用 `**npm run build:homeserver`**（脚本 `scripts/build-homeserver.mjs` 会从 `**ecosystem.config.cjs` 的 `env**` 注入 `VITE_PUBLIC_BASE_PATH`、`VITE_ROOM_TOKEN`、`VITE_ICE_SERVERS_JSON`，避免前端仍是默认 `change-me` 而后端已是自定义 `ROOM_TOKEN`）。若手写构建，必须保证 `**VITE_ROOM_TOKEN` 与服务器 `ROOM_TOKEN` 完全一致**：

```bash
VITE_PUBLIC_BASE_PATH=/surveillance VITE_ROOM_TOKEN=<与 ecosystem env.ROOM_TOKEN 相同> npm run build -w web
```

关键说明：

- `PUBLIC_BASE_PATH`：服务端生产模式挂载静态资源的路径；同时决定 `{PUBLIC_BASE_PATH}/api`、`{PUBLIC_BASE_PATH}/socket.io/`。公网子路径部署时使用 `/surveillance`。
- `VITE_PUBLIC_BASE_PATH`：前端构建时的 base path 和 React Router basename；未单独设置 `VITE_SOCKET_PATH` 时，前端会将 socket.io path、ICE 请求路径推导为 `{base}/socket.io/`、`{base}/api/ice-servers`。公网子路径部署时应使用 `/surveillance`。
- `ROOM_TOKEN` 与 `VITE_ROOM_TOKEN`：第一版简易房间口令，必须保持一致。
- `ICE_SERVERS_JSON`：服务端 `{PUBLIC_BASE_PATH}/api/ice-servers` 返回值。
- `VITE_ICE_SERVERS_JSON`：前端在 ICE API 不可用时的兜底配置。
- `ALLOWED_ORIGINS`：需包含浏览器地址栏的 **完整 Origin**（协议 + 主机名 + 端口，无路径）。公网若同时使用 `**https://kaitool.top` 与 `https://www.kaitool.top`**，两条都要写（浏览器只会带当前访问的那一个）。
- `PORT=3333`：家庭云的 `3000` 端口已被占用，生产服务固定使用 `3333`。

如果后续接入 coturn，`ICE_SERVERS_JSON` 示例：

```env
ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":["turn:www.kaitool.top:3478?transport=udp","turn:www.kaitool.top:3478?transport=tcp"],"username":"turn-user","credential":"turn-password"}]
```

生产环境不建议长期把固定 TURN 密码暴露给前端。当前 MVP 先支持配置入口，后续应改成服务端签发短期 TURN 凭证。

## 5. 构建与启动

### 5.1 本地开发

```bash
npm install
npm run dev
```

`npm run dev` 会经 `scripts/run-dev.mjs` 应用 `ecosystem.config.cjs` 的 `env_development`（含 `VITE_*`），与直接改 ecosystem 一处即可。

本地默认：

- 前端：`http://localhost:5173`
- 服务端：`http://localhost:3000`
- Vite 将 `{VITE_PUBLIC_BASE_PATH}/api` 与 `{VITE_PUBLIC_BASE_PATH}/socket.io` 代理到服务端（未设 base 时为 `/api`、`/socket.io`）。

测试地址：

```text
http://localhost:5173/camera/home
http://localhost:5173/viewer/home
```

### 5.2 生产构建

家庭云生产环境使用 `3333` 端口，并部署到 `/surveillance` 子路径。构建前确保：

```env
VITE_PUBLIC_BASE_PATH=/surveillance
PUBLIC_BASE_PATH=/surveillance
NODE_ENV=production

```

然后执行。注意：`VITE_PUBLIC_BASE_PATH` 是前端构建期变量，必须在构建时生效；项目已提供家庭云专用构建脚本：

```bash

VITE_PUBLIC_BASE_PATH=/surveillance npm run build
```

### 5.4 Tailscale HTTPS

因为旧手机调用摄像头必须运行在 HTTPS 安全上下文中，所以不要让 `mi10ultra` 访问：

```text
http://100.65.192.69:3333/surveillance/camera/home
```

推荐在 `homeserver` 上用 Tailscale Serve 将 HTTPS 域名转发到本机 `3333` 端口。当前实现下 **信令与 ICE REST 均在 `{PUBLIC_BASE_PATH}` 前缀下**（生产一般为 `/surveillance/socket.io/`、`/surveillance/api/`），因此只需保证 `**/surveillance/`*（含其下的 socket.io 长轮询与 WS 升级）** 到达 Node；若使用「整站转发」命令则一并覆盖。

示例思路：

```bash
tailscale serve --https=443 / http://127.0.0.1:3333
```

具体命令以当前 Tailscale 版本为准，可用 `tailscale serve --help` 查看。目标是让以下地址全部由 Tailscale HTTPS 域名代理到本机服务：

```text
https://homeserver.tailed5977.ts.net/surveillance/camera/home
https://homeserver.tailed5977.ts.net/surveillance/viewer/home
https://homeserver.tailed5977.ts.net/surveillance/socket.io/
https://homeserver.tailed5977.ts.net/surveillance/api/ice-servers
```

排查：若采集页「信令连接」长期为未连接、「采集端状态」卡在连接信令中，请确认 `**https://域名/surveillance/socket.io/**`（或你配置的 `PUBLIC_BASE_PATH` 下的 `/socket.io/`）与 `**…/api/**` 能到达 Node；仅静态资源命中而 API/socket 未反代仍会失败。

### 5.5 systemd 示例

当前更推荐 PM2（配置集中在 `ecosystem.config.cjs`）。若不用 PM2，也可以用 systemd **直接调用 Node**，并把环境与 PM2 `env` 对齐（不要用 `EnvironmentFile=.env`，除非你明确只在开发机使用）：

```ini
[Unit]
Description=Home Surveillance
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/home-surveillance
Environment=NODE_ENV=production
Environment=PORT=3333
Environment=PUBLIC_BASE_PATH=/surveillance
Environment=ROOM_TOKEN=change-me
Environment=MAX_VIEWERS_PER_ROOM=2
Environment=ALLOWED_ORIGINS=https://homeserver.tailed5977.ts.net,https://www.kaitool.top
Environment=ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"}]
ExecStart=/usr/bin/node ./server/dist/index.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

变量较多时，更省事的做法仍是：**用 PM2 托管**，单一真相仍为 `ecosystem.config.cjs`。

## 6. Nginx 反向代理

阿里云 `aliserver` 的 Nginx 反向代理到 `homeserver`：

```nginx
server {
    listen 80;
    server_name www.kaitool.top;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name www.kaitool.top;

    ssl_certificate /etc/letsencrypt/live/www.kaitool.top/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/www.kaitool.top/privkey.pem;

    location /surveillance/ {
        proxy_pass http://100.65.192.69:3333/surveillance/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

`location /surveillance/` 同时覆盖静态页、`/surveillance/api/*` 与 `**/surveillance/socket.io/**`。当前 Socket.IO path 已与 `**PUBLIC_BASE_PATH**` 对齐。

## 7. 分阶段实施路线

### 第一阶段：家庭内网 MVP

目标：

- `homeserver` 跑通 Node.js 和前端页面。
- `mi10ultra` 通过家庭 Wi-Fi 或 Tailscale 访问 camera 页面并成功获取摄像头。
- 局域网 viewer 能看到画面。
- HTTPS 安全上下文验证通过。

验收：

- camera 本地预览正常。
- viewer 能收到远程 stream。
- 关闭 viewer 后 camera 清理 peer。
- 服务端只处理信令，不处理视频流。
- `GET /healthz` 和 `/api/ice-servers` 正常返回。
- `npm run typecheck` 和 `npm run build` 通过。

### 第二阶段：Tailscale 私有访问

目标：

- `homeserver`、`aliserver`、`mi10ultra` 均已加入 Tailscale。
- 外部自用设备通过 Tailscale 访问 viewer 页面。
- 验证 WebRTC ICE 候选路径和连接成功率。
- 验证 Tailscale MagicDNS 和 HTTPS Certificates 是否满足摄像头授权要求。

验收：

- 外部手机开启 Tailscale 后能访问 `homeserver` 的 `100.65.192.69` 或 MagicDNS 域名。
- 信令连接稳定。
- WebRTC 能建连或明确显示失败原因。
- UI 能区分 socket 状态、camera 在线状态和 WebRTC 状态。

### 第三阶段：阿里云公网入口

目标：

- `aliserver` 使用 `100.115.222.54` 加入同一 Tailnet。
- Nginx 通过 Tailscale 反代 `homeserver` 的 `100.65.192.69`。
- 公网域名支持 HTTPS 和 WSS。

验收：

- `https://www.kaitool.top/surveillance` 能打开页面。
- socket.io 能通过 Nginx 正常升级 WebSocket。
- camera 和 viewer 信令能互通。
- `/surveillance/camera/home` 和 `/surveillance/viewer/home` 前端路由刷新后仍能打开。

### 第四阶段：coturn 兜底

目标：

- 阿里云部署 coturn。
- 前端 ICE 配置加入 TURN。
- 公网复杂网络下仍能观看。
- 使用 Trickle ICE 先验证 coturn，再接入业务代码。

验收：

- 安全组放行 TURN 所需 UDP/TCP 端口。
- 能观察到 relay candidate。
- 在 P2P 失败网络中可以通过 TURN 建连。
- coturn 不允许匿名 relay，凭证不长期硬编码到前端。

### 第五阶段：安全与可用性增强

目标：

- 增加鉴权、房间口令、viewer 限制、错误提示和重连。

验收：

- 未授权用户不能加入房间。
- camera 离线时 viewer 有明确提示。
- TURN 凭证不长期硬编码。
- 日志不泄漏敏感信令。

## 8. coturn 部署要点

coturn 建议部署在 `aliserver`，因为它拥有独立公网 IPv4。

安全组至少放行：

```text
TCP 80
TCP 443
UDP 3478
TCP 3478
UDP 49160-49200
```

示例 `turnserver.conf` 关键项：

```conf
listening-port=3478
fingerprint
lt-cred-mech
realm=www.kaitool.top
external-ip=<阿里云公网 IPv4>
user=turn-user:turn-password
min-port=49160
max-port=49200
no-cli
```

上线前先用 [Trickle ICE](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/) 验证：

- 出现 `srflx`：STUN 正常。
- 出现 `relay`：TURN 中继正常。

## 9. 关键风险清单

- `mi10ultra` 虽然已接入 Tailscale，但摄像头权限仍依赖 HTTPS 安全上下文，不能只用裸 IP HTTP。
- Tailscale 解决的是网络层连通，WebRTC 最终媒体路径仍由 ICE 选路决定。
- HTTP 内网页面无法稳定调用摄像头，必须解决 HTTPS。
- Nginx 不能代理 WebRTC UDP 媒体流。
- STUN 不是兜底方案，TURN 才是。
- TURN relay 会消耗阿里云带宽和流量。
- coturn 端口、安全组或 `external-ip` 配错时，可能表现为信令成功但视频无画面。
- Mesh 不适合多人观看。
- 旧手机长时间运行可能因发热、省电策略或锁屏导致采集中断。
- 当前 MVP 使用 `ROOM_TOKEN` 简易鉴权，不适合直接作为长期公网安全模型。
- `VITE_ROOM_TOKEN` 会进入前端构建产物，公网分享场景下需要尽快升级为短期 token。

## 10. 最终推荐

最终架构建议如下：

