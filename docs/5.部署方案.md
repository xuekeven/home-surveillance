# 云边混合 WebRTC 家庭监控系统部署方案

本文档承接 `[1.方案选择.md](1.方案选择.md)`、`[2.技术学习.md](2.技术学习.md)`、`[3.技术架构.md](3.技术架构.md)`，并根据当前代码实现更新。本文专注于部署节点、环境变量、构建启动方式、Nginx/coturn 配置、验收步骤与风险清单。

## 1. 部署建议

### 1.1 家庭服务器

节点信息：

- 节点名：`homeserver`
- Tailscale IP：`100.65.192.69`
- 角色：主服务节点
- 网络：家庭 Wi-Fi 内网、IPv6、Tailscale

运行：

- Node.js 服务：`server/dist/index.js`。
- 前端静态文件：`web/dist`，生产模式由 Node.js 服务托管。
- Tailscale。
- Tailscale MagicDNS 和 HTTPS Certificates。

建议：

- 使用 systemd 或 Docker Compose 保活。
- 固定家庭服务器内网 IP。
- 配置健康检查接口，例如 `/healthz`。
- 日志区分信令日志和访问日志。
- 默认不直接暴露公网端口，公网入口由 `aliserver` 反向代理。
- 旧手机和自用观看端优先访问家庭服务器的 HTTPS 域名，避免裸 IP HTTP 导致摄像头权限失败。
- Node.js 建议使用 20 LTS 或更新的 LTS 版本。

### 1.2 阿里云

节点信息：

- 节点名：`aliserver`
- Tailscale IP：`100.115.222.54`
- 角色：公网网关与 TURN 兜底节点
- 网络：独立公网 IPv4、Tailscale

运行：

- Nginx。
- coturn。
- Tailscale。

建议：

- Nginx 配置 Let's Encrypt 证书。
- 安全组只开放必要端口。
- Nginx 通过 Tailscale 反向代理到 `homeserver` 的 `100.65.192.69`。
- coturn relay 端口范围收窄，便于安全组管理。
- 监控 TURN 带宽，避免异常消耗。
- coturn 必须配置公网 `external-ip`，避免返回云厂商 VPC 内网地址。
- 使用 Trickle ICE 验证 `srflx` 和 `relay` candidate，确认 STUN/TURN 都真正可用。

### 1.3 旧安卓手机

节点信息：

- 节点名：`mi10ultra`
- Tailscale IP：`100.126.250.4`
- 角色：采集端
- 网络：家庭 Wi-Fi、IPv6、Tailscale

建议：

- 使用稳定电源供电。
- 关闭过度省电策略。
- 保持屏幕或浏览器前台运行，实际机型需要测试。
- 降低分辨率和帧率，减少发热。
- 优先使用后置摄像头。
- 优先访问家庭服务器的 HTTPS 域名，而不是裸 IP HTTP。
- 长时间运行时关注 Tailscale、电池、发热和浏览器后台保活策略。

## 3. 当前代码能力

当前 MVP 已实现：

- Express + socket.io 信令服务。
- `ROOM_TOKEN` 简易入房鉴权。
- 单房间单 camera。
- 单房间最大 viewer 数量限制，默认 `2`。
- `join-room`、`signal`、`viewer-joined`、`viewer-left`、`camera-left`、`room-state`、`room-error`。
- `/healthz` 健康检查。
- `/api/ice-servers` 下发 ICE servers。
- Vite + React 前端。
- `/camera/:roomId` 采集端页面。
- `/viewer/:roomId` 观看端页面。
- simple-peer WebRTC Mesh。
- 基础 socket/WebRTC/ICE 状态展示。
- 生产模式由 Node.js 托管 `web/dist`。
- 前端 `BrowserRouter` 已支持 `VITE_PUBLIC_BASE_PATH`，可部署到 `/surveillance` 子路径。

当前暂未实现：

- 用户系统。
- 管理后台。
- TURN 短期凭证签发。
- 视频录制。
- 移动侦测。
- 多 camera 管理。
- SFU 架构。
- PWA 后台保活。

## 4. 环境变量

以 `.env.example` 为准，生产环境建议在 `homeserver` 创建 `.env`：

```env
PORT=3000
NODE_ENV=production
PUBLIC_BASE_PATH=/surveillance
ROOM_TOKEN=change-me
MAX_VIEWERS_PER_ROOM=2
ALLOWED_ORIGINS=https://www.kaitool.top,https://home-server.your-tailnet.ts.net,http://localhost:5173,http://localhost:3000
ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":"stun:global.stun.twilio.com:3478"}]
VITE_PUBLIC_BASE_PATH=/surveillance
VITE_SOCKET_PATH=/socket.io/
VITE_ROOM_TOKEN=change-me
VITE_ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":"stun:global.stun.twilio.com:3478"}]
```

关键说明：

- `PUBLIC_BASE_PATH`：服务端生产模式挂载静态资源的路径。公网子路径部署时使用 `/surveillance`。
- `VITE_PUBLIC_BASE_PATH`：前端构建时的 base path 和 React Router basename。公网子路径部署时也应使用 `/surveillance`。
- `ROOM_TOKEN` 与 `VITE_ROOM_TOKEN`：第一版简易房间口令，必须保持一致。
- `ICE_SERVERS_JSON`：服务端 `/api/ice-servers` 返回值。
- `VITE_ICE_SERVERS_JSON`：前端在 `/api/ice-servers` 不可用时的兜底配置。
- `ALLOWED_ORIGINS`：需要包含公网域名、Tailscale HTTPS 域名和本地开发地址。

如果后续接入 coturn，`ICE_SERVERS_JSON` 示例：

```env
ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":["turn:www.kaitool.top:3478?transport=udp","turn:www.kaitool.top:3478?transport=tcp"],"username":"turn-user","credential":"turn-password"}]
```

生产环境不建议长期把固定 TURN 密码暴露给前端。当前 MVP 先支持配置入口，后续应改成服务端签发短期 TURN 凭证。

## 6. Nginx 反向代理

阿里云 `aliserver` 的 Nginx 反向代理到 `homeserver`：

```nginx
server {
    listen 80;
    server_name www.kaitool.top;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name www.kaitool.top;

    ssl_certificate /etc/letsencrypt/live/www.kaitool.top/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/www.kaitool.top/privkey.pem;

    location /surveillance/ {
        proxy_pass http://100.65.192.69:3000/surveillance/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /socket.io/ {
        proxy_pass http://100.65.192.69:3000/socket.io/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "Upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

当前代码里 socket.io path 是 `/socket.io/`，没有挂到 `/surveillance/socket.io/`。如果未来想把 WebSocket 也放到 `/surveillance/socket.io/`，必须同时改：

- `VITE_SOCKET_PATH`
- 服务端 socket.io path
- Nginx `location`

## 7. 分阶段实施路线

### 第一阶段：家庭内网 MVP

目标：

- `homeserver` 跑通 Node.js 和前端页面。
- `mi10ultra` 通过家庭 Wi-Fi 或 Tailscale 访问 camera 页面并成功获取摄像头。
- 局域网 viewer 能看到画面。
- HTTPS 安全上下文验证通过。

验收：

- camera 本地预览正常。
- viewer 能收到远程 stream。
- 关闭 viewer 后 camera 清理 peer。
- 服务端只处理信令，不处理视频流。
- `GET /healthz` 和 `/api/ice-servers` 正常返回。
- `npm run typecheck` 和 `npm run build` 通过。

### 第二阶段：Tailscale 私有访问

目标：

- `homeserver`、`aliserver`、`mi10ultra` 均已加入 Tailscale。
- 外部自用设备通过 Tailscale 访问 viewer 页面。
- 验证 WebRTC ICE 候选路径和连接成功率。
- 验证 Tailscale MagicDNS 和 HTTPS Certificates 是否满足摄像头授权要求。

验收：

- 外部手机开启 Tailscale 后能访问 `homeserver` 的 `100.65.192.69` 或 MagicDNS 域名。
- 信令连接稳定。
- WebRTC 能建连或明确显示失败原因。
- UI 能区分 socket 状态、camera 在线状态和 WebRTC 状态。

### 第三阶段：阿里云公网入口

目标：

- `aliserver` 使用 `100.115.222.54` 加入同一 Tailnet。
- Nginx 通过 Tailscale 反代 `homeserver` 的 `100.65.192.69`。
- 公网域名支持 HTTPS 和 WSS。

验收：

- `https://www.kaitool.top/surveillance` 能打开页面。
- socket.io 能通过 Nginx 正常升级 WebSocket。
- camera 和 viewer 信令能互通。
- `/surveillance/camera/home` 和 `/surveillance/viewer/home` 前端路由刷新后仍能打开。

### 第四阶段：coturn 兜底

目标：

- 阿里云部署 coturn。
- 前端 ICE 配置加入 TURN。
- 公网复杂网络下仍能观看。
- 使用 Trickle ICE 先验证 coturn，再接入业务代码。

验收：

- 安全组放行 TURN 所需 UDP/TCP 端口。
- 能观察到 relay candidate。
- 在 P2P 失败网络中可以通过 TURN 建连。
- coturn 不允许匿名 relay，凭证不长期硬编码到前端。

### 第五阶段：安全与可用性增强

目标：

- 增加鉴权、房间口令、viewer 限制、错误提示和重连。

验收：

- 未授权用户不能加入房间。
- camera 离线时 viewer 有明确提示。
- TURN 凭证不长期硬编码。
- 日志不泄漏敏感信令。

## 8. coturn 部署要点

coturn 建议部署在 `aliserver`，因为它拥有独立公网 IPv4。

安全组至少放行：

```text
TCP 80
TCP 443
UDP 3478
TCP 3478
UDP 49160-49200
```

示例 `turnserver.conf` 关键项：

```conf
listening-port=3478
fingerprint
lt-cred-mech
realm=www.kaitool.top
external-ip=<阿里云公网 IPv4>
user=turn-user:turn-password
min-port=49160
max-port=49200
no-cli
```

上线前先用 [Trickle ICE](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/) 验证：

- 出现 `srflx`：STUN 正常。
- 出现 `relay`：TURN 中继正常。

## 9. 关键风险清单

- `mi10ultra` 虽然已接入 Tailscale，但摄像头权限仍依赖 HTTPS 安全上下文，不能只用裸 IP HTTP。
- Tailscale 解决的是网络层连通，WebRTC 最终媒体路径仍由 ICE 选路决定。
- HTTP 内网页面无法稳定调用摄像头，必须解决 HTTPS。
- Nginx 不能代理 WebRTC UDP 媒体流。
- STUN 不是兜底方案，TURN 才是。
- TURN relay 会消耗阿里云带宽和流量。
- coturn 端口、安全组或 `external-ip` 配错时，可能表现为信令成功但视频无画面。
- Mesh 不适合多人观看。
- 旧手机长时间运行可能因发热、省电策略或锁屏导致采集中断。
- 当前 MVP 使用 `ROOM_TOKEN` 简易鉴权，不适合直接作为长期公网安全模型。
- `VITE_ROOM_TOKEN` 会进入前端构建产物，公网分享场景下需要尽快升级为短期 token。

## 10. 最终推荐

最终架构建议如下：

```text
家庭服务器：主服务节点
  - homeserver
  - 100.65.192.69
  - Node.js signaling
  - Web 静态资源
  - Tailscale

旧安卓手机：采集端
  - mi10ultra
  - 100.126.250.4
  - 家庭 Wi-Fi
  - Tailscale
  - Browser camera app
  - SimplePeer

阿里云：公网网关和 TURN 兜底
  - aliserver
  - 100.115.222.54
  - Nginx HTTPS/WSS reverse proxy
  - coturn STUN/TURN
  - Tailscale

观看端：
  - 自用：优先 Tailscale 链路
  - 家人/临时：公网域名链路
```

实现优先级：

1. 先让 `homeserver` 和 `mi10ultra` 在局域网 / Tailscale 内跑通。
2. 再用 Tailscale 解决自用远程访问。
3. 然后在 `aliserver` 配置 Nginx，解决公网网页和信令入口。
4. 最后接 coturn 解决复杂 NAT 下的视频可达性。
