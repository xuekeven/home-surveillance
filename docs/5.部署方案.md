# 云边混合 WebRTC 家庭监控系统部署方案

本文档承接 [技术学习](2.技术学习.md) 与 [技术架构](3.技术架构.md)，并按当前代码实现更新。本文专注于部署节点、环境变量、构建启动方式、Nginx/coturn 配置、验收步骤与风险清单。

## 1. 部署建议

以下节点信息是部署清单，不是实时状态快照。当前在线性、直连/DERP 路径和延迟应通过 `tailscale status`、`tailscale ping` 与 `tailscale netcheck` 验证。

### 1.1 家庭云

节点信息：

- 节点名：`homeserver`
- Tailscale IP：`100.65.192.69`
- Tailscale HTTPS 域名：`homeserver.tailed5977.ts.net`
- 角色：主服务节点
- 网络：家庭 Wi-Fi 内网、IPv6、Tailscale
- 服务端口：`3333`
- 部署子路径：`/surveillance`

运行：

- Node.js 服务：`server/dist/index.js`。
- 前端静态文件：`web/dist`，生产模式由 Node.js 服务托管。
- PM2：生产进程管理。
- Tailscale。
- Tailscale MagicDNS 和 HTTPS Certificates。

建议：

- 使用 PM2 保活，项目已提供 `ecosystem.config.cjs`。
- 固定家庭云内网 IP。
- 配置健康检查接口，例如 `/healthz`。
- 日志区分信令日志和访问日志。
- 默认不直接暴露公网端口，公网入口由 `aliserver` 反向代理。
- 旧手机必须通过 HTTPS 域名访问采集页，例如 `https://homeserver.tailed5977.ts.net/surveillance/camera/home`，否则浏览器不会稳定授予摄像头权限。
- 当前 Vite 8 要求 Node.js `^20.19.0 || >=22.12.0`；建议使用满足该范围的当前 LTS 版本。

### 1.2 阿里云

节点信息：

- 节点名：`aliserver`
- Tailscale IP：`100.115.222.54`
- 角色：公网网关与 TURN 兜底节点
- 网络：独立公网 IPv4、Tailscale

运行：

- Nginx。
- coturn。
- Tailscale。

建议：

- Nginx 配置 Let's Encrypt 证书。
- 安全组只开放必要端口。
- Nginx 通过 Tailscale 反向代理到 `homeserver` 的 `100.65.192.69`。
- coturn relay 端口范围收窄，便于安全组管理。
- 监控 TURN 带宽，避免异常消耗。
- coturn 必须配置公网 `external-ip`，避免返回云厂商 VPC 内网地址。
- 使用 Trickle ICE 验证 `srflx` 和 `relay` candidate，确认 STUN/TURN 都真正可用。

### 1.3 旧安卓手机

节点信息：

- 节点名：`mi10ultra`
- Tailscale IP：`100.126.250.4`
- 角色：采集端
- 网络：家庭 Wi-Fi、IPv6、Tailscale

建议：

- 使用稳定电源供电。
- 关闭过度省电策略。
- 保持屏幕或浏览器前台运行，实际机型需要测试。
- 降低分辨率和帧率，减少发热。
- 优先使用后置摄像头。
- 优先访问家庭云的 HTTPS 域名，而不是裸 IP HTTP。
- 长时间运行时关注 Tailscale、电池、发热和浏览器后台保活策略。

## 3. 当前代码能力

当前已实现：

- Express 5 + socket.io 信令服务；生产托管 `web/dist`。
- `ROOM_TOKEN` 入房鉴权（前端构建需与之对齐）。
- 房间策略持久化（`server/data/`）：房间启用、陌生人脸告警开关、**每房间 `maxViewersPerRoom`**（JSON 未写该字段时回退 **`MAX_VIEWERS_PER_ROOM` 环境变量**，默认 **2**，范围 1–99；后台可按房间覆盖）。
- 后台 `/admin`：`ADMIN_TOKEN` **非空** 时可用 `{PUBLIC_BASE_PATH}/api/admin/*`；未配置时相关接口返回 **503** `admin_not_configured`（见 [server/src/apiRoutes.ts](../server/src/apiRoutes.ts) 的 `requireAdmin`）。
- 家庭成员向量库；采集端在浏览器内执行告警识别与陌生人抓拍，观看端可手动开启本地识别叠加；服务端负责 JSON 数据、截图落盘和企微中转，不解码视频。
- 企微告警：`WEWORK_RELAY_*`、`FACE_ALERT_ORIGIN_*`、`FACE_ALERT_COOLDOWN_MS`。
- `join-room`、`signal`、`viewer-joined`、`viewer-left`、`camera-left`、`room-state`、`room-error`。
- 多摄像头：`camera-catalog`（采集端上报设备列表）、`switch-camera` / `viewer-switch-camera` / `camera-switch-failed`（观看端请求切换、采集端执行或失败回传）。
- `/healthz`；`{PUBLIC_BASE_PATH}/api/ice-servers`；Vite + React；simple-peer Mesh。当前 ICE 接口不鉴权，不能安全地下发长期 TURN 密码。
- 前端支持 `VITE_PUBLIC_BASE_PATH` 子路径部署。

当前暂未实现：

- 视频录制。
- 移动侦测。
- 统一后台多路 camera 账号管理（当前仅单采集端内多设备切换）。
- SFU 架构。
- PWA 后台保活。

## 4. 环境变量

**单一配置来源：仓库根目录 `.env`**（模板见 [.env.example](../.env.example)）。与本仓库当前实现对齐的方式：

- **服务端**：`server/src/config.ts` 在启动时用 dotenv 加载根 `.env`（与是否 PM2、是否 `production` 无关）。PM2 使用的 `ecosystem.config.cjs` **仅指定进程入口与工作目录**，不在文件内嵌一长串 `env`，请在机器上放置与生产一致的 `.env` 或由宿主环境导出同名变量。
- **本地开发**：`pnpm dev` 先由 `scripts/run-dev.mjs` 读取根 `.env` 再并发启动 `server` 与 `web`；若 `.env` 不存在则仅打印告警，子进程仍启动（与 `build:prod` 不同）。
- **前端构建期**：`pnpm build:prod`（`scripts/build-prod.mjs`）**要求**根目录存在 `.env`，读取后把 `PUBLIC_BASE_PATH` / `ROOM_TOKEN` / `ICE_SERVERS_JSON` 等注入为 `VITE_*`。当 `VITE_PUBLIC_BASE_PATH` 与 `PUBLIC_BASE_PATH` 都未设置时，脚本对 web 构建会回退默认 **`/surveillance`**（与服务端 `PUBLIC_BASE_PATH` 无自动绑定，生产请显式对齐两者）。若手写构建，须自行导出 `VITE_PUBLIC_BASE_PATH`、`VITE_ROOM_TOKEN`、`VITE_ICE_SERVERS_JSON` 且 **`VITE_ROOM_TOKEN` 与 `ROOM_TOKEN` 完全一致**。

生产示例（按实际域名修改 `ALLOWED_ORIGINS`；`MAX_VIEWERS_PER_ROOM` 可选，省略则默认 **2**，与房间 JSON 中显式写的 `maxViewersPerRoom` 并存时以后者为准）：

```env
PORT=3333
NODE_ENV=production
PUBLIC_BASE_PATH=/surveillance
ROOM_TOKEN=replace-with-a-long-random-token
MAX_VIEWERS_PER_ROOM=2
ALLOWED_ORIGINS=https://homeserver.tailed5977.ts.net,https://www.kaitool.top,http://localhost:5173,http://localhost:3333
ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":"stun:global.stun.twilio.com:3478"}]

WEWORK_RELAY_URL=
WEWORK_RELAY_API_KEY=
WEWORK_RELAY_TOUSER=
FACE_ALERT_ORIGIN_PRIMARY=https://homeserver.tailed5977.ts.net
FACE_ALERT_ORIGIN_SECONDARY=https://www.kaitool.top
FACE_ALERT_COOLDOWN_MS=120000

ADMIN_TOKEN=
```

可选构建覆盖（未设置时 `build-prod` 会用 `PUBLIC_BASE_PATH` / `ROOM_TOKEN` / `ICE_SERVERS_JSON` 推导）：

```env
VITE_PUBLIC_BASE_PATH=/surveillance
VITE_ROOM_TOKEN=replace-with-the-same-room-token
VITE_ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"}]
VITE_PUBLIC_ORIGIN=https://www.kaitool.top
VITE_INTERNAL_ORIGIN=https://homeserver.tailed5977.ts.net
```

手写仅构建前端示例：

```bash
VITE_PUBLIC_BASE_PATH=/surveillance VITE_ROOM_TOKEN=<与 ROOM_TOKEN 相同> pnpm --filter @home-surveillance/web build
```

关键说明：

- `PUBLIC_BASE_PATH`：静态资源、`{PUBLIC_BASE_PATH}/api`、`{PUBLIC_BASE_PATH}/socket.io/`（及同前缀的 `GET …/healthz`）。公网子路径示例 `/surveillance`。
- `VITE_PUBLIC_BASE_PATH`：前端 base / Router basename；未单独设置 `VITE_SOCKET_PATH` 时，`socket.io-client` 的 `path` 默认为 `{VITE_PUBLIC_BASE_PATH}/socket.io/`（见 [web/src/config.ts](../web/src/config.ts)）。
- `VITE_SOCKET_URL`：可选；非空时作为 Socket.IO 连接使用的基准 URL（页面与信令非同源时常用）。
- `VITE_SOCKET_PATH`：可选；显式覆盖 Socket.IO path，默认由 `VITE_PUBLIC_BASE_PATH` 推导。
- `VITE_PUBLIC_ORIGIN` / `VITE_INTERNAL_ORIGIN`：后台房间列表生成公网和内网采集/查看入口时使用的 Origin，不带 `/surveillance`；任一变量留空时，对应入口使用当前后台页面的 Origin（`location.protocol + '//' + location.host`）。
- `ROOM_TOKEN` / `VITE_ROOM_TOKEN`：简易房间口令，须一致。
- `ICE_SERVERS_JSON` / `VITE_ICE_SERVERS_JSON`：服务端 ICE 接口与前端兜底。
- `ALLOWED_ORIGINS`：须包含浏览器 **Origin**（协议 + 主机 + 端口）；未设置时服务端默认仅允许 `http://localhost:5173` 与 `http://localhost:3000`（见 [server/src/config.ts](../server/src/config.ts)）。若同时使用 `https://kaitool.top` 与 `https://www.kaitool.top`，两条都要写。该配置只约束 Socket.IO 的浏览器 CORS，不替代认证。
- `WEWORK_RELAY_*`、`FACE_ALERT_*`：陌生人脸企微告警；留空 relay 则服务端跳过调用。
- `ADMIN_TOKEN`：非空则启用 `/api/admin/*`（后台页面 `/admin`）。
- `PORT`：示例为家庭云 `3333`；未设置时服务端默认 **`3000`**（见 [server/src/config.ts](../server/src/config.ts)），与 Vite 开发代理默认后端端口一致；请以 `.env` 为准。
- `MAX_VIEWERS_PER_ROOM`：可选；持久化策略里未写 `maxViewersPerRoom` 时，会与配置值合并并经 **1–99** 钳位（见 [server/src/persist/roomPoliciesRepo.ts](../server/src/persist/roomPoliciesRepo.ts)）。默认 **2**。加入观看端时的上限来自策略中的 `maxViewersPerRoom`（已为规范化值），逻辑见 [server/src/socket.ts](../server/src/socket.ts)。

如果后续接入 coturn，`ICE_SERVERS_JSON` 示例：

```env
ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":["turn:www.kaitool.top:3478?transport=udp","turn:www.kaitool.top:3478?transport=tcp"],"username":"turn-user","credential":"turn-password"}]
```

生产环境不建议长期把固定 TURN 密码暴露给前端。后续应改成服务端签发短期 TURN 凭证。

## 5. 构建与启动

### 5.1 本地开发

```bash
pnpm install
pnpm dev
```

`pnpm dev` 会经 `scripts/run-dev.mjs` 加载根 `.env`，再启动 server 与 Vite。

本地默认（以 `.env` 中 `PORT` 为准，示例常为 `3333`）：

- 前端：`http://localhost:5173`
- 服务端：`http://localhost:<PORT>`（未配置 `PORT` 时服务端默认 `3000`）
- Vite 将 `{VITE_PUBLIC_BASE_PATH}/api` 与 `{VITE_PUBLIC_BASE_PATH}/socket.io` 代理到服务端（未设 base 时为 `/api`、`/socket.io`）。

测试地址（根目录 `.env` 中 **`VITE_PUBLIC_BASE_PATH` 为空或未设** 时，Vite `base` 为 `/`，路径如下；若开发环境也设为 `/surveillance`，则三段路径前须加 `/surveillance` 前缀）：

```text
http://localhost:5173/camera/home
http://localhost:5173/viewer/home
http://localhost:5173/admin
```

### 5.2 生产构建

家庭云生产环境使用 `3333` 端口，并部署到 `/surveillance` 子路径。构建前确保：

```env
VITE_PUBLIC_BASE_PATH=/surveillance
PUBLIC_BASE_PATH=/surveillance
NODE_ENV=production
PORT=3333
```

然后执行。注意：`VITE_PUBLIC_BASE_PATH` 是前端构建期变量，必须在构建时生效；推荐使用：

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm build:prod
```

`build:prod` 会编译 `web` 与 `server`，并从根 `.env` 注入 `VITE_*`。

如果不用脚本，也可以显式传入：

```bash
VITE_PUBLIC_BASE_PATH=/surveillance pnpm build
```

### 5.3 PM2 启动

项目根目录已提供 `ecosystem.config.cjs`，可直接启动：

```bash
pnpm dlx pm2 start ecosystem.config.cjs
pnpm dlx pm2 save
```

常用命令：

```bash
pnpm dlx pm2 status
pnpm dlx pm2 logs home-surveillance
pnpm dlx pm2 restart home-surveillance
pnpm dlx pm2 stop home-surveillance
```

如需开机自启：

```bash
pnpm dlx pm2 startup
pnpm dlx pm2 save
```

PM2 **不**在 `ecosystem.config.cjs` 内嵌环境变量块；请在服务器上配置根 `.env`（或与下文 systemd 相同的一组 `Environment=`），再启动进程。典型取值示例：

```text
PORT=3333
NODE_ENV=production
PUBLIC_BASE_PATH=/surveillance
ALLOWED_ORIGINS=https://homeserver.tailed5977.ts.net,https://www.kaitool.top,http://localhost:5173,http://localhost:3333
```

生产启动后，家庭云本机或 Tailscale 内网可访问：

```text
http://100.65.192.69:3333/healthz
http://100.65.192.69:3333/surveillance/api/ice-servers
http://100.65.192.69:3333/surveillance/camera/home
http://100.65.192.69:3333/surveillance/viewer/home
```

旧手机采集端应使用 HTTPS 域名访问：

```text
https://homeserver.tailed5977.ts.net/surveillance/camera/home
```

观看端自用通道：

```text
https://homeserver.tailed5977.ts.net/surveillance/viewer/home
```

### 5.4 Tailscale HTTPS

因为旧手机调用摄像头必须运行在 HTTPS 安全上下文中，所以不要让 `mi10ultra` 访问：

```text
http://100.65.192.69:3333/surveillance/camera/home
```

推荐在 `homeserver` 上用 Tailscale Serve 将 HTTPS 域名转发到本机 `3333` 端口。当前实现下，信令与 ICE REST 均在 `{PUBLIC_BASE_PATH}` 前缀下（生产一般为 `/surveillance/socket.io/`、`/surveillance/api/`），因此必须保证整个 `/surveillance/` 路径（包括 Socket.IO 长轮询和 WebSocket 升级）到达 Node；使用整站转发时会一并覆盖。

示例思路：

```bash
tailscale serve --https=443 / http://127.0.0.1:3333
```

具体命令以当前 Tailscale 版本为准，可用 `tailscale serve --help` 查看。目标是让以下地址全部由 Tailscale HTTPS 域名代理到本机服务：

```text
https://homeserver.tailed5977.ts.net/surveillance/camera/home
https://homeserver.tailed5977.ts.net/surveillance/viewer/home
https://homeserver.tailed5977.ts.net/surveillance/socket.io/
https://homeserver.tailed5977.ts.net/surveillance/api/ice-servers
```

排查：若采集页「信令连接」长期未连接、状态卡在连接信令中，请确认 `https://域名/surveillance/socket.io/`（或实际 `PUBLIC_BASE_PATH` 下的 `/socket.io/`）与同前缀的 `/api/` 都能到达 Node；仅静态资源命中而 API 或 Socket.IO 未反代仍会失败。

### 5.5 systemd 示例

当前更推荐 PM2（`ecosystem.config.cjs` 指定入口与工作目录，变量来自根 `.env` 或宿主导出）。若不用 PM2，也可以用 systemd **直接调用 Node**，并把环境与 `.env` 对齐（不要把敏感 `.env` 提交到仓库）：

```ini
[Unit]
Description=Home Surveillance
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/home-surveillance
ExecStart=/usr/bin/node ./server/dist/index.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

服务端会通过 dotenv 直接加载 `/opt/home-surveillance/.env`；无需在 unit 中重复声明 `EnvironmentFile`。将 `.env` 权限限制为仅服务账号可读。

## 6. Nginx 反向代理

阿里云 `aliserver` 的 Nginx 反向代理到 `homeserver`：

```nginx
server {
    listen 80;
    server_name www.kaitool.top;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name www.kaitool.top;

    ssl_certificate /etc/letsencrypt/live/www.kaitool.top/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/www.kaitool.top/privkey.pem;

    location /surveillance/ {
        client_max_body_size 15m;
        proxy_pass http://100.65.192.69:3333/surveillance/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

`location /surveillance/` 同时覆盖静态页、`/surveillance/api/*` 与 `/surveillance/socket.io/`。当前 Socket.IO path 已与 `PUBLIC_BASE_PATH` 对齐。

## 7. 分阶段实施路线

### 第一阶段：家庭内网 MVP

目标：

- `homeserver` 跑通 Node.js 和前端页面。
- `mi10ultra` 通过家庭 Wi-Fi 或 Tailscale 访问 camera 页面并成功获取摄像头。
- 局域网 viewer 能看到画面。
- HTTPS 安全上下文验证通过。

验收：

- camera 本地预览正常。
- viewer 能收到远程 stream。
- 关闭 viewer 后 camera 清理 peer。
- 服务端只处理信令，不处理视频流。
- `pnpm typecheck` 和 `pnpm build` 通过。
- `GET /healthz`（及生产子路径部署时的 `GET {PUBLIC_BASE_PATH}/healthz`）与 `GET {PUBLIC_BASE_PATH}/api/ice-servers`（无子路径时为 `/api/ice-servers`）正常返回。

### 第二阶段：Tailscale 私有访问

目标：

- `homeserver`、`aliserver`、`mi10ultra` 均已加入 Tailscale。
- 外部自用设备通过 Tailscale 访问 viewer 页面。
- 验证 WebRTC ICE 候选路径和连接成功率。
- 验证 Tailscale MagicDNS 和 HTTPS Certificates 是否满足摄像头授权要求。

验收：

- 外部手机开启 Tailscale 后能访问 `homeserver` 的 `100.65.192.69` 或 MagicDNS 域名。
- 信令连接稳定。
- WebRTC 能建连或明确显示失败原因。
- UI 能区分 socket 状态、camera 在线状态和 WebRTC 状态。

### 第三阶段：阿里云公网入口

目标：

- `aliserver` 使用 `100.115.222.54` 加入同一 Tailnet。
- Nginx 通过 Tailscale 反代 `homeserver` 的 `100.65.192.69`。
- 公网域名支持 HTTPS 和 WSS。

验收：

- `https://www.kaitool.top/surveillance` 能打开页面。
- socket.io 能通过 Nginx 正常升级 WebSocket。
- camera 和 viewer 信令能互通。
- `/surveillance/camera/home` 和 `/surveillance/viewer/home` 前端路由刷新后仍能打开。

### 第四阶段：coturn 兜底

目标：

- 阿里云部署 coturn。
- 前端 ICE 配置加入 TURN。
- 公网复杂网络下仍能观看。
- 使用 Trickle ICE 先验证 coturn，再接入业务代码。

验收：

- 安全组放行 TURN 所需 UDP/TCP 端口。
- 能观察到 relay candidate。
- 在 P2P 失败网络中可以通过 TURN 建连。
- coturn 不允许匿名 relay，凭证不长期硬编码到前端。

### 第五阶段：安全与可用性增强

目标：

- 将现有共享 `ROOM_TOKEN` 升级为按房间、角色和设备签发的短期 token。
- 增加账号登录、接口与 Socket 限流、TURN 短期凭据和最小权限数据接口。
- 保留现有 viewer 数量限制、错误提示和重连能力并补充自动化测试。

验收：

- 未授权用户不能加入房间，观看端凭据不能冒充采集端或访问其他房间。
- camera 离线时 viewer 有明确提示。
- ICE 接口不公开长期 TURN 凭据。
- 日志不泄漏敏感信令、token、人脸资料或 TURN 密码。

## 8. coturn 部署要点

coturn 建议部署在 `aliserver`，因为它拥有独立公网 IPv4。

安全组至少放行：

```text
TCP 80
TCP 443
UDP 3478
TCP 3478
UDP 49160-49200
```

示例 `turnserver.conf` 关键项：

```conf
listening-port=3478
fingerprint
lt-cred-mech
realm=www.kaitool.top
external-ip=<阿里云公网 IPv4>
user=turn-user:turn-password
min-port=49160
max-port=49200
no-cli
```

上线前先用 [Trickle ICE](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/) 验证：

- 出现 `srflx`：STUN 正常。
- 出现 `relay`：TURN 中继正常。

## 9. 关键风险清单

- `mi10ultra` 虽然已接入 Tailscale，但摄像头权限仍依赖 HTTPS 安全上下文，不能只用裸 IP HTTP。
- Tailscale 解决的是网络层连通，WebRTC 最终媒体路径仍由 ICE 选路决定。
- HTTP 内网页面无法稳定调用摄像头，必须解决 HTTPS。
- Nginx 不能代理 WebRTC UDP 媒体流。
- STUN 不是兜底方案，TURN 才是。
- TURN relay 会消耗阿里云带宽和流量。
- coturn 端口、安全组或 `external-ip` 配错时，可能表现为信令成功但视频无画面。
- Mesh 不适合多人观看。
- 旧手机长时间运行可能因发热、省电策略或锁屏导致采集中断。
- 当前 MVP 使用 `ROOM_TOKEN` 简易鉴权，不适合直接作为长期公网安全模型。
- `VITE_ROOM_TOKEN` 会进入前端构建产物，公网分享场景下需要尽快升级为短期 token。

## 10. 最终推荐

最终架构建议如下：

```text
家庭云：主服务节点
  - homeserver
  - 100.65.192.69
  - Node.js signaling
  - Web 静态资源
  - Tailscale

旧安卓手机：采集端
  - mi10ultra
  - 100.126.250.4
  - 家庭 Wi-Fi
  - Tailscale
  - Browser camera app
  - SimplePeer

阿里云：公网网关和 TURN 兜底
  - aliserver
  - 100.115.222.54
  - Nginx HTTPS/WSS reverse proxy
  - coturn STUN/TURN
  - Tailscale

观看端：
  - 自用：优先 Tailscale 链路
  - 家人/临时：公网域名链路
```

实现优先级：

1. 先让 `homeserver` 和 `mi10ultra` 在局域网 / Tailscale 内跑通。
2. 再用 Tailscale 解决自用远程访问。
3. 然后在 `aliserver` 配置 Nginx，解决公网网页和信令入口。
4. 最后接 coturn 解决复杂 NAT 下的视频可达性。
