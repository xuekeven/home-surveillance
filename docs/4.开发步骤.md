# 开发步骤

本文档根据 `[1.方案选择.md](1.方案选择.md)`、`[2.技术学习.md](2.技术学习.md)`、`[3.技术架构.md](3.技术架构.md)` 整理后续代码修改计划。

## 1. 开发目标

实现一个最小可用的云边混合 WebRTC 家庭监控系统：

- `homeserver` 运行 Node.js 信令服务和前端页面。
- `mi10ultra` 打开采集端页面，获取摄像头并作为 camera 入房。
- viewer 打开观看端页面，加入同一房间并接收 WebRTC 视频流。
- 信令通过 socket.io 透传，媒体流通过 WebRTC Mesh 传输。
- ICE servers 支持 STUN，并预留阿里云 coturn TURN 配置。
- 前端展示基础连接状态，便于排查 HTTPS、WebSocket、ICE、TURN 问题。

## 3. 第一阶段：项目初始化

### 3.1 根目录工程配置

新增：

- `package.json`
- `.gitignore`
- `env.development.example`（可选：复制为根目录 `.env` 做本地覆盖；开发与生产主配置均在 `ecosystem.config.cjs`）

根 `package.json` 计划提供脚本：

```json
{
  "scripts": {
    "dev": "concurrently \"npm run dev -w server\" \"npm run dev -w web\"",
    "build": "npm run build -w server && npm run build -w web",
    "typecheck": "npm run typecheck -w server && npm run typecheck -w web"
  },
  "workspaces": [
    "server",
    "web"
  ]
}
```

### 3.2 环境变量

- **开发与生产**：均以根目录 `ecosystem.config.cjs` 为准：`env_development`（本地、`npm run dev`、`pm2 --env development`）与 `env`（生产 PM2）。
- **可选**：将根目录 `env.development.example` 复制为 `.env`，仅在本地覆盖同名变量。

示例字段（见 ecosystem 内注释与真实字典项）：

```env
PORT=3333
PUBLIC_BASE_PATH=/surveillance
ROOM_TOKEN=change-me
ALLOWED_ORIGINS=https://www.kaitool.top,https://home-server.your-tailnet.ts.net,http://localhost:5173
ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"}]
```

说明：

- `ROOM_TOKEN` 用于第一阶段简易鉴权。
- `ICE_SERVERS_JSON` 后续可加入 `turn:www.kaitool.top:3478`。
- `PUBLIC_BASE_PATH` 用于兼容阿里云 Nginx 的 `/surveillance` 子路径。
- `ALLOWED_ORIGINS` 需要同时覆盖公网域名、Tailscale HTTPS 域名和本地开发地址。

## 4. 第二阶段：服务端信令服务

### 4.1 配置模块

新增 `server/src/config.ts`：

- 读取端口。
- 读取允许跨域来源。
- 读取房间 token。
- 解析 ICE servers。
- 校验关键配置，启动时失败尽早暴露。

### 4.2 类型定义

新增 `server/src/types.ts`：

```ts
type Role = 'camera' | 'viewer'

interface JoinRoomPayload {
  roomId: string
  role: Role
  token: string
}

interface SignalPayload {
  roomId: string
  to: string
  signal: unknown
}
```

### 4.3 房间状态管理

新增 `server/src/rooms.ts`：

- `joinCamera(roomId, socketId)`
- `joinViewer(roomId, socketId)`
- `removeClient(socketId)`
- `getRoom(roomId)`
- `getClient(socketId)`
- `listViewers(roomId)`

约束：

- 第一阶段每个房间只允许一个 camera。
- camera 重复加入时，旧 camera 断开或拒绝新 camera，需要在实现前二选一。
- viewer 断开时通知 camera。
- camera 断开时通知所有 viewer。

建议默认策略：

- 同一房间新 camera 加入时拒绝，并返回 `room-error`。

### 4.4 鉴权模块

新增 `server/src/auth.ts`：

- 校验 `JoinRoomPayload.token === ROOM_TOKEN`。
- 后续可以替换为短期 token 或管理端签发。

### 4.5 socket.io 事件

新增 `server/src/socket.ts`：

实现事件：

- `join-room`
- `signal`
- `viewer-joined`
- `viewer-left`
- `camera-left`
- `room-state`
- `room-error`

服务端原则：

- 只透传 `signal`。
- 不解析和保存 SDP。
- 不打印完整 ICE candidate。
- 对 `roomId`、`role`、`to` 做基础校验。

### 4.6 HTTP 服务

新增 `server/src/index.ts`：

- 创建 Express。
- 暴露 `/healthz`。
- 预留 `/api/ice-servers`，后续用于下发 STUN/TURN 配置或短期 TURN 凭证。
- 挂载 socket.io。
- 生产模式下托管 `web/dist` 静态资源。
- 支持 `/surveillance` base path。

验收：

- `GET /healthz` 返回 `{ "ok": true }`。
- `GET /api/ice-servers` 返回前端可用的 ICE servers。
- socket.io 可以连接。
- 未带 token 加入房间会失败。
- camera 加入后 viewer 加入能触发 `viewer-joined`。

## 5. 第三阶段：前端公共能力

### 5.1 前端配置

新增 `web/src/config.ts`：

- 读取 `VITE_SOCKET_URL`。
- 读取 `VITE_SOCKET_PATH`。
- 读取 `VITE_PUBLIC_BASE_PATH`。
- 读取 `VITE_ROOM_TOKEN`。
- 优先从服务端 `/api/ice-servers` 获取 ICE servers，失败时使用构建变量兜底。

建议：

- 第一阶段 ICE servers 可通过构建变量配置。
- `/api/ice-servers` 后续可扩展为签发 TURN 短期凭证，避免把长期 TURN 密码写死在前端。

### 5.2 socket 客户端

新增 `web/src/shared/socket.ts`：

- 创建 socket.io-client。
- 统一处理连接、断开、错误。
- 支持自定义 path，例如 `/socket.io/`。
- 支持公网域名、Tailscale HTTPS 域名和本地开发地址三种访问方式。

### 5.3 WebRTC 配置

新增 `web/src/shared/rtc.ts`：

- 导出 `getIceServers()`。
- 导出 `createCameraPeer(localStream)`。
- 导出 `createViewerPeer()`。
- 统一 simple-peer 配置。

### 5.4 状态模型

新增 `web/src/shared/status.ts`：

定义 UI 状态：

- `idle`
- `connecting-socket`
- `waiting-camera`
- `waiting-viewer`
- `connecting-webrtc`
- `connected`
- `disconnected`
- `error`

## 6. 第四阶段：采集端页面

### 6.1 页面入口

新增：

- `web/src/camera/CameraPage.tsx`
- `web/src/camera/useCameraRoom.ts`

路由：

```text
/camera/:roomId
```

公网子路径：

```text
/surveillance/camera/:roomId
```

### 6.2 摄像头采集

实现：

- 页面加载后检查 `window.isSecureContext`。
- 调用 `navigator.mediaDevices.getUserMedia()`。
- 默认启用视频，音频先做成可配置。
- 本地 `<video muted playsInline autoPlay>` 预览。
- 捕获权限拒绝、设备不存在、非 HTTPS 等错误。
- 优先适配 `mi10ultra` 作为长期前台采集设备，保留低分辨率/低帧率配置入口，降低发热。

建议默认媒体参数：

```ts
{
  video: {
    facingMode: 'environment',
    width: { ideal: 1280 },
    height: { ideal: 720 },
    frameRate: { ideal: 20, max: 30 }
  },
  audio: false
}
```

### 6.3 camera 房间逻辑

实现：

- socket 连接成功后发送 `join-room`，角色为 `camera`。
- 维护 `Map<viewerSocketId, SimplePeer.Instance>`。
- 收到 `viewer-joined` 后创建 initiator peer。
- peer 触发 `signal` 时发给指定 viewer。
- 收到 viewer 的 `signal` 后调用对应 peer 的 `signal()`。
- 收到 `viewer-left` 后销毁 peer。
- 页面卸载时关闭所有 peer 和 media tracks。

### 6.4 camera UI

展示：

- 当前房间号。
- 本机角色：camera。
- HTTPS 安全上下文状态。
- 摄像头权限状态。
- socket 状态。
- viewer 数量。
- 每个 viewer 的连接状态。
- 错误信息和重试按钮。

## 7. 第五阶段：观看端页面

### 7.1 页面入口

新增：

- `web/src/viewer/ViewerPage.tsx`
- `web/src/viewer/useViewerRoom.ts`

路由：

```text
/viewer/:roomId
```

公网子路径：

```text
/surveillance/viewer/:roomId
```

### 7.2 viewer 房间逻辑

实现：

- socket 连接成功后发送 `join-room`，角色为 `viewer`。
- 等待 camera 发来的 `signal`。
- 首次收到 signal 时创建 non-initiator peer。
- peer 触发 `signal` 时发回 camera。
- peer 触发 `stream` 时绑定远端 `<video>`。
- 处理 camera 离线、socket 断开、peer error。

### 7.3 viewer UI

展示：

- 当前房间号。
- 本机角色：viewer。
- socket 状态。
- camera 在线状态。
- WebRTC 状态。
- 远程视频播放状态。
- 错误信息和重连按钮。

## 8. 第六阶段：连接质量与 ICE 可观测性

实现基础调试能力：

- 显示 simple-peer `connect`、`close`、`error` 状态。
- 在开发模式下打印简化 ICE 信息。
- 使用 `RTCPeerConnection.getStats()` 尝试识别 candidate 类型：
  - `host`
  - `srflx`
  - `relay`
- UI 中显示当前是否疑似走 TURN relay。
- 明确区分 Tailscale 网络层连通和 WebRTC ICE 选路结果：不能假设开启 Tailscale 后媒体一定走 Tailnet。

注意：

- 不打印完整 SDP。
- 不打印完整 candidate 地址到生产日志。

## 9. 第七阶段：构建与部署适配

### 9.1 Vite base path

`web/vite.config.ts` 支持：

```ts
base: process.env.VITE_PUBLIC_BASE_PATH || '/'
```

需要验证：

- 本地开发根路径可用。
- `/surveillance/` 子路径下静态资源路径正确。

### 9.2 socket.io path

前端和 Nginx 保持一致：

```ts
path: '/socket.io/'
```

如果未来希望 socket 也挂在 `/surveillance/socket.io/`，需要同步修改：

- 前端 socket path。
- 服务端 socket.io path。
- Nginx location。

### 9.3 生产静态资源

服务端生产模式托管：

```text
server serves web/dist
```

并支持 SPA fallback：

```text
/camera/:roomId -> index.html
/viewer/:roomId -> index.html
```

## 13. Review 检查点

开始开发前，需要你确认：

- 是否接受 `server/` + `web/` 的双包 workspace 结构。
- 前端是否使用 React + Vite + TypeScript。
- 第一版是否使用 `ROOM_TOKEN` 作为简易鉴权。
- 单房间最大 viewer 数是否先限制为 2。
- 是否第一版就加入 TURN 配置入口，但不强制部署 coturn。
- socket.io 路径是否保持 `/socket.io/`，公网路径只用于页面 `/surveillance/`。
